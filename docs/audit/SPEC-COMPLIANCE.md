# Spec compliance check (task 6)

## Sources

The published DOGFOOD pages (`https://dogfoodhack.com/` and `/spec/`) could not be
fetched from the build environment: its network policy refuses `dogfoodhack.com`.
The requirements below are therefore taken from the copies of the spec already in
this repository, and each is marked with where it comes from:

- **[checker]** `run.py`, the official acceptance checker, and `.dogfood.toml`;
- **[brief]** requirement wording quoted from the brief in the code and docs (for
  example `DOGFOOD T2: "a track judge must never see another track"`);
- **[plan]** `docs/reference/dogfood-2026-implementation-plan-colorful.pdf`, which
  restates the tiers, constraints and deliverables, and `docs/PLAN.md`.

Re-run this check against the live pages once they are reachable, to catch any
requirement that none of those copies mention.

## Result

- Official checker against a fresh database on this branch: **7 of 7 checks pass,
  T1 and T2 verified** (the run is in `acceptance-report.txt`, task 8).
- 39 of the 40 requirements below were already met, with test evidence. The one that was not
  (the audit log was append-only by convention only, where the plan asks for a
  database-level guarantee) is fixed on this branch.

## Threat model the brief names

Sybil voting, ballot stuffing, judge collusion and deadline gaming are each covered
in `docs/THREAT-MODEL.md` (entries 25-28) with what is and is not stopped.
Denial of service is now entry 32.

## Plan items deliberately not followed

| Plan item | What the code does | Assessment |
|---|---|---|
| Scores never mutated; corrections create a versioned row | A rescore updates the row | Acceptable: every score write is an audit entry with its raw total, and the audit log is now immutable, so the history is still recoverable. Documented rather than changed, since versioned rows would change every score query |
